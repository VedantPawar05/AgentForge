# ADR-002: Hardened Sandbox Execution Model (Docker / MicroVM Dual-Driver)

## Status

Accepted

## Context

AgentForge executes untrusted code generated by AI models and cloned from external repositories. The execution environment must run builds, package installations, and test suites without exposing the host OS, internal networks, or control-plane credentials to compromise, escape, or resource exhaustion.

Standard Docker containers alone do not provide sufficient multi-tenant isolation against kernel-level exploits or host network scanning (e.g., SSRF against `169.254.169.254`). Conversely, requiring enterprise microVM infrastructure (like AWS Firecracker or E2B) for local developer laptops introduces heavy dependencies and cost friction.

## Decision

We establish a **Pluggable Sandbox Driver Interface (`ISandboxDriver`)** supporting two execution profiles:

1. **Local Development Profile (`DockerSandboxDriver`)**:
   - Uses local Docker daemon with hardened security flags.
   - Run as non-root user (`UID 1000:GID 1000`).
   - Read-only root filesystem (`--read-only`), mounting only `/workspace` and `/tmp` as volatile tmpfs.
   - Drop all capabilities (`--cap-drop ALL`).
   - Strict cgroups limits: `--cpus=2`, `--memory=2g`, `--pids-limit=100`.
   - Host Docker socket `/var/run/docker.sock` is strictly forbidden from being mounted.
   - Network egress restricted or disabled (`--network none` by default; allowed package registry proxy if egress required).

2. **Cloud / Production Profile (`MicroVMSandboxDriver`)**:
   - Integrates with E2B / Firecracker microVM execution sandboxes.
   - Hardware-level virtualization (KVM) ensures full guest OS kernel isolation per execution attempt.
   - Automated sub-second lifecycle provisioning and teardown.

## Consequences

### Positive:

- Local developer workflow remains free and self-contained without requiring cloud credentials or special hypervisor privileges.
- Production deployment gains true hardware virtualization boundary against hostile code.
- Uniform interface (`executeCommand`, `copyFileIn`, `copyFileOut`, `cleanup`) ensures worker business logic is completely agnostic to whether code is executing locally in Docker or remotely in a microVM.

### Negative:

- Two drivers must be maintained and verified against the sandbox integration test suite.
